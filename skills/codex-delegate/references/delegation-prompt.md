# 위탁 프롬프트 템플릿

Codex는 이 대화를 볼 수 없고, 프롬프트에 적힌 것만 압니다. 프롬프트 품질이 곧 결과물 품질입니다. 아래 템플릿의 각 섹션이 왜 필요한지 이해하고 작성하세요.

## 템플릿

```markdown
# 작업 위탁: <작업 제목>

## 프로젝트 컨텍스트
- 저장소: <경로>, <스택 요약 (런타임, 프레임워크, 패키지 매니저)>
- 검증 명령: <테스트/빌드/린트 명령어 — 예: pnpm test, pnpm build>
- 반드시 따를 프로젝트 규칙:
  <CLAUDE.md/AGENTS.md에서 이 작업에 실제로 적용되는 규칙만 발췌.
   예: 테스트 약화 금지, 필드명 변환 규칙, 에러 클래스 사용 등>

## 구현 계획 (이 계획대로 구현하세요)
<계획 전문. 파일 경로, 작업 순서, 인터페이스 시그니처, 데이터 구조까지
 구체적으로. 대화에서 결정된 사항을 빠짐없이 옮겨 적을 것.>

## 범위 제한
- 수정 허용: <파일/디렉토리 목록>
- 수정 금지: <공유 계약 파일, 무관한 코드. 병렬 위탁이면 다른 태스크의 영역>
- 계획에 없는 리팩토링·구조 변경 금지. 계획대로 진행이 불가능한 지점을
  발견하면 임의로 우회하지 말고, 그 사실을 최종 보고에 명시하세요.

## 완료 기준
- 계획의 모든 항목이 구현됨
- `<테스트 명령>` 통과 (테스트 스킵·단언 제거·조건 완화 금지)
- `<빌드/린트 명령>` 통과
- 새 로직에는 테스트를 함께 작성

## 최종 보고 형식 (마지막 메시지에 반드시 포함)
1. 변경 파일 목록과 각 파일의 변경 요지
2. 실행한 검증 명령과 결과 (실패했다면 실패한 그대로 보고)
3. 계획과 다르게 구현한 부분과 그 이유
4. 미완료 항목·불확실한 지점 (없으면 "없음")
```

## 작성 원칙

**모호함은 위탁 전에 제거합니다.** "알아서 적절히"가 프롬프트에 들어가면 그 부분의 설계 결정권을 Codex에 넘긴 것입니다. 계획에 애매한 지점이 있으면 Claude가 먼저 결정해서 명시하거나 사용자에게 확인하세요.

**계획 파일 전달 — 규모로 방식을 정합니다.** 계획이 파일로 있으면(design-review를 거친 플랜 문서 등):

- **보통 규모(대략 수백 줄 이하)면 전문을 프롬프트에 포함하세요 (기본).** 이 정도 길이는 구현 중 Codex가 코드 탐색에 쓰는 토큰에 비하면 미미해서 비용·품질 어느 쪽에도 부담이 없고, 완독이 보장되며, 프롬프트 파일 자체가 "무엇을 발주했는지"의 완결된 기록이 됩니다.
- **계획서가 매우 크거나 대부분이 이번 태스크와 무관하면** 해당 태스크 관련 섹션만 발췌해 넣고, 나머지는 한 단락으로 요약하세요. 그리고 원본 파일을 Codex가 읽을 수 있게 보장한 뒤(아래) "시작 전에 <경로> 전문을 읽고 구현하라"를 완료 기준에 넣으세요.
- **참조 방식을 쓸 때 파일 가용성은 직접 확인하세요.** worktree에서 실행되면 미커밋 플랜 파일은 존재하지 않습니다 — 커밋해 두거나 worktree 안으로 복사하세요. 참조 방식의 실패 모드는 프롬프트 길이가 아니라 "파일이 없거나, 일부만 읽는 것"입니다.
- 어느 방식이든 원본 경로를 출처로 병기하고, 리뷰 과정에서 확정됐지만 계획서 본문에 없는 결정 사항(리뷰 코멘트 등)도 반영해서 옮기세요.

**규칙은 발췌해서 넣습니다.** Codex는 저장소의 `AGENTS.md`를 자동으로 읽지만, 그것에 의존하지 마세요 — 이 작업에 실제로 적용되는 핵심 규칙(테스트 정책, 네이밍/변환 규칙, 금지 사항)은 프롬프트에 직접 적어야 지켜집니다.

**완료 기준은 명령어로 씁니다.** "잘 동작해야 함"이 아니라 "`pnpm test` 통과"처럼 Codex가 스스로 실행해서 확인할 수 있는 형태로 씁니다.

**보고 형식을 강제하는 이유**: 4번(미완료·불확실 항목)이 있어야 Codex가 어물쩍 넘어간 부분이 드러나고, 5단계 검증에서 어디를 집중적으로 봐야 할지 알 수 있습니다.

**병렬 위탁일 때 추가 사항:**
- 각 프롬프트의 "수정 금지"에 **다른 태스크가 소유한 파일·디렉토리**를 명시하세요.
- 선행 확정된 공유 계약(스키마, API 명세, 공용 타입)은 "이미 확정됨, 수정 금지, 이 인터페이스에 맞춰 구현"으로 명시하고 해당 내용(또는 파일 경로)을 프롬프트에 포함하세요.
- 프롬프트에 적는 경로는 해당 worktree 기준 상대 경로로 쓰세요.
